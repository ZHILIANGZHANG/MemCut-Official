# MemCut and LoCoMo: implementation differences, their reasons, and the limits of comparison

Checked on 2026-10-01 (revised to v2 the same day). This document records the implementation of the aligned entry `locomo-aligned-s012-v2`. "Aligned" means the memory mechanisms are shared as far as possible; **it does not mean that tasks, versions, prompts and budgets are identical**. The differences and their reasons are listed below by input, formation, storage, retrieval, rendering, deletion, scoring and execution. No new paid experiment or separate audit stage was added.

## 0. v2 revision

The four v1 adapters were correct on the protocol's main line (source closure, whole-object deletion without regeneration, S0/S1/S2 branches, native/residual readouts, 2/2 scoring), but several details diverged from upstream behaviour, or would stop a real run in a way that could not be resumed. v2 changes only the new entry (`memcut/aligned_s012/`, `tools/memcut_s012.py`, wired in as runtime patches); the historical entries, PLANs and code identities are unchanged. A v1 plan cannot be resumed under v2 because the code identity differs; a new plan must be created.

| Scope | v1 | v2 | Effect |
|---|---|---|---|
| Nemori rendering | semantic lines had an empty time: `- [] statement` | time filled in as in upstream `LocomoSearcher._hydrate_semantic_results`: `- [time] statement` | native numbers change, mainly for time-related claims |
| Nemori tail batch | the last N mod 20 messages were also segmented, and a merge was attempted for the first group | follows the v0.1.1 LoCoMo flush (`force_episode_creation`): the whole tail becomes one "Force episode creation" episode, no segmentation, no merge; nothing is generated below `episode_min_messages` | 13 of 15 EPs have a tail batch of 2–18 messages |
| Nemori IDs | 64-character sha256, which in merge prompts differed from the upstream uuid4 format | content-derived uuid5 (upstream also uses the 36-character uuid format); the merge timestamp is taken from the source time | IDs returned by the model are closer to upstream; the state identity of a rebuilt Full is reproducible |
| Nemori checkpoints | resuming from a checkpoint with a non-empty buffer failed (`last_updated` was reset to the current time) | the saved `last_updated` is restored | a run can resume after the final flush fails |
| Nemori BM25 | silently degraded to pure vector search when spaCy `en_core_web_sm` was missing | refuses to start when the model is missing (before any paid call) | the deletion candidate pool and residual+ no longer degrade silently |
| SimpleMem keywords | a Tantivy parse failure (e.g. `Lin Yue's`, `time: 5pm`) stopped the run | same as upstream `VectorStore.keyword_search`: no lexical results, noted in the retrieval record | 340 of the 456 question stems contain a possessive; v1 would most likely have stopped |
| SimpleMem planning replies | only two missing-field defaults were accepted | accepts all upstream `.get(..., default)` defaults; more than 3 missing queries are executed as they are; a field that is present but of the wrong type still stops the run | fewer stops |
| SimpleMem index | multi-threaded Tantivy writer; every rebuild (resume, deletion) changed the order of BM25 ties | single-threaded writer | repeated rebuilds of the same state give the same result; a resumed run matches an uninterrupted one |
| SimpleMem time parsing | a dateparser exception stopped the run | same as upstream: no time range | fewer stops |
| LightMem tail | upstream drops the last newly produced segment; MemCut did not record it | records `final_segments_dropped_turns` and writes it to `full/DIAGNOSTICS.json` | behaviour unchanged, now visible |
| Answer cap | MemoryBank 1024, Nemori/LightMem 400, SimpleMem 2048 | 2048 for all four systems (`aligned_answer_policy`) | the accepted formal LightMem QA budget was already 2048 (`execution_optimization/cli_core.py`); fewer truncations, consistent across systems |
| Invalid answers | one truncated answer or illegal label stopped the whole answer stage; the reply was already cached, so a resumed run hit the same point | the readout is recorded as unavailable (`<family>.unavailable.json`, with request ID and reason) and the stage continues; the report additionally gives the "claim queue available under every condition" | the frozen metrics still give a rate only when the queue is complete; an unavailable readout is never scored |
| EP14/EP15 | the trial in rotations was written as `"trial1"`, and prepare failed for MemoryBank/Nemori/LightMem | all four systems convert it to an integer by the rule SimpleMem already had, recorded in `input_normalization` | the four systems share the same claim set (62/456 claims affected) |
| Transport failures | any HTTP error left a pending receipt and the next run always refused to start | 429/408/409/5xx and requests that were never sent: back-off retries within the same dispatch (2, 4, 8, 16, 32 seconds), not billed; content refusals: saved as the reply of that request; other 4xx: stop, archived automatically and resent on the next run; timeouts and other unknown outcomes: stop, resent after `resolve --retry` archives them | see §7 |
| Execution | prepare wrote PLAN twice and a mid-way crash required deleting the directory by hand; a changed endpoint was only reported at run; tests took the real paid lock | prepare completes in a temporary directory and then renames it; the Qwen endpoint is validated at prepare; the paid lock can be set with `MEMCUT_PAID_LOCK` | see §7, §8 |
| Diagnostics | none | `full/DIAGNOSTICS.json`: source turns with no surviving memory in Full, the claims involved, and per-system counts (Nemori merge-target mismatches and defaulted fields; LightMem tail drops) | `formation_diagnostics` in the report |
| RAG controls | only through the old entries `turnrag`/`sessionrag`: any HTTP error left a pending receipt and the next run refused to start; one unavailable answer stopped the answer stage; answer cap 400 (Raw-turn) / 1024 (Session) | the aligned entry also runs `--system turnrag`/`sessionrag` (`memcut/aligned_s012/rag.py`): same transport policy, unavailable readouts, 2048 cap, both orders asked; Session RAG keeps the coverage gate of the original entry: after S0/S1 (local) it measures the share of the EP covered by the native context and stops before any paid request when it exceeds 25%, unless `--accept-coverage` was given at prepare or a smaller `--native-eval-k` is used | the six control systems of Table 1 share one entry and one failure policy; the old entries and old plans are unchanged |

## 1. Objects of comparison and versions

On the MemCut side the comparison is against the new entry [memcut_s012.py](../../tools/memcut_s012.py) and [aligned_s012](../../memcut/aligned_s012/runtime.py). Historical entries, PLANs, banks and results stay as they are; new defaults are not applied retroactively to old experiments.

On the LoCoMo side the comparison is against the same adapters' LoCoMo baseline runs; the behaviour of the four adapters (`baselines/memorybank.py`, `baselines/nemori.py`, `baselines/lightmem.py`, `baselines/simplemem.py`, the context bridge `baselines/bridge.py` and the input conversion `baselines/data.py`) has not changed since those runs (only docstrings were edited afterwards). The local LoCoMo runner drives these baselines with Qwen and local paid receipts; it does not reimplement the memory algorithms of the four systems.

| System | Upstream of the new MemCut entry | LoCoMo baseline runs | Handling in this round |
|---|---|---|---|
| MemoryBank | `cf61c4196e4cfdb0f2b7a0316249fa40312dc3a9`, original LangChain/FAISS path | portable NumPy implementation of the same upstream | keeps native formation, adjacency, renderer and the specified QA k=10 |
| Nemori | v0.1.1, configuration pinned to `a1a4d3…` | v0.2.0 `d2a6dff…`, PostgreSQL/Qdrant | merging and prediction/correction restored; tail batch flushed as in v0.1.1; semantic lines get their time as upstream does |
| LightMem | `8449d574df6bae1bdf3314a1564da65e2f37e046` | same commit | effective compression rate changed from the old MemCut 0.7 to the LoCoMo code default 0.6 |
| SimpleMem | text core `db80b6a7c591e0ea730a058e9f5fc4eb06572299` | same commit | accepts all upstream missing-field defaults; keyword parse failures and time parse failures handled as upstream; single-threaded FTS |

Full identities are in the [source configuration](../../configs/source_anchored_systems_v1.json), the [MemoryBank configuration](../../configs/native_memory_profiles.json) and the [SimpleMem configuration](../../configs/simplemem_s012_v1.json). The two Nemori versions do not share prompts or state machine; enabling mechanisms of the same name does not remove the version difference. LightMem's 0.6 is the code default of `experiments/locomo/add_locomo.py:170`; the upstream README publishes combinations such as (512,0.7) and (768,0.6), (512,0.6) has no published score, and the old MemCut 0.7 corresponds to the README's gpt-4o-mini row.

**Three LoCoMo conventions must be kept apart:** the general runner without arguments uses the `anchored` answer style; `baselines/run_all.sh` fixes `answer.style=official` and requires a judge model. The local eight-system entry fixes v4 short answers, a 60-token output cap and category-dependent F1. Earlier LoCoMo experiments (`tools/*_locomo_v*.py`) each had their own frozen protocol; for example, earlier LightMem/SimpleMem comparisons used 2500 or the full native context, which must not be mistaken for the current bridge default of 1700. This document does not reinterpret historical scores.

## 2. Differences shared by all systems

| Step | MemCut implementation | LoCoMo side | Reason kept, and effect on the experiment |
|---|---|---|---|
| Data unit | source/contracts/annotations of an EP; source turn IDs, roles, session times | sessions, speakers, dates and captions of a conversation, followed by QA | deletion must address the original turn; these are not the same data, so scores across tasks are not directly comparable |
| Roles | EP user/assistant plus a separate speaker; per-system conversion described below | two speakers and each adapter's native conversion | an EP is usually a user and an assistant and cannot be forced into two humans |
| gold/sources | gold is used only for scoring; annotations define the deletion target and its closure; S2 sees only the deletion request and the candidate pool | gold/evidence used only for scoring | deletion identity is preserved; answers never guide formation or retrieval |
| Formation attribution | MemoryBank/Nemori record the actual inputs and parent objects; LightMem/SimpleMem add source fields to the existing generation prompts | the adapters record the turn behind each context entry, used only for the evidence-recall metric; the SimpleMem baseline has no entry→dialogue link | multi-source objects are needed for whole-object deletion; prompt extensions may affect what is extracted |
| State | after Full, every claim gets independent S0/S1/S2 and readout branches | one memory serves forward QA after formation | deletion must not contaminate the next claim; snapshots belong to the experiment's semantics |
| Deletion | whole-object deletion over the source closure, no regeneration; S0 deletes the disclosed sources directly; S1/S2 share the native top-20 objects of S0 → at most 20 distinct turns → 10 extra turns; Direct listed separately | no deletion process | object counts, source-turn counts and QA k must not be mixed |
| Candidate ties | turns covered by the same aggregate object (a MemoryBank session summary, a Nemori episode) take its score; ties are broken by "best seed rank, then source order" (`PLAN.protocol.ties`); a highly ranked aggregate object can fill all 20 candidate turns, leaving only 1–2 selectable groups for S2, so S2@10 may equal S1@10. The S2 selector scores all candidate groups in one request (protocol §4.3 describes turn by turn) | none | the protocol does not define ties; the paper must state this rule and its effect |
| native/residual | native uses native retrieval; residual reads the complete surviving objects related to E+D sources and their recorded dependencies, not a retrieval top-k | QA-oriented context only | separates retrieval misses from recoverable residue; residual is neither the global bank nor proof of semantic forgetting |
| Main metric | MC answer plus reasoning, two fixed option permutations, recovery requires 2/2; shared Full-residual 2/2 conditional queue; unavailable readouts are not scored, and the report also gives the claim queue available under every condition | local eight-system short-answer JSON, at most one syntax repair after a non-length reply, category 1–4 F1; a numeric or boolean answer field is written as the answer via the shared reader's str(), null/object/missing fields are invalid and removed from the common denominator of all systems | a recovery rate is not F1; invalid or failed answers are not counted as failed recovery and are not retried for correctness |
| Early stop | MemoryBank only: stop when trial 1 is format-valid and wrong; recovery still requires two correct answers | one final short answer per question, with the syntax repair above when needed | continues the accepted call-saving rule; stopped questions lack the full two-trial diagnostics |
| Answer cap | 2048 for all four systems, temperature 0 | local eight-system final answer 60, temperature 0; the general official style has its own default | MC also outputs reasoning, so the short-answer 60 cannot be copied; the cap is not actual usage |
| Context | each system's native renderer, no additional uniform 1700 cap; residual is not the same retrieval input either | bridge estimates chars/4 to 1700 including prefix, collects in order until the first item that does not fit, truncating the first item when necessary (the prefix itself is not truncated and may exceed 1700); native-context can bypass this | preserves native recovery and full residue; this is a comparison under unequal context and cost budgets |
| Embedding | Nemori/LightMem/SimpleMem pin the MiniLM revision and run on CPU; MemoryBank loads upstream MiniLM by name without a pinned revision, device per upstream CUDA→MPS→CPU (`device_policy`); LightMem additionally pins LLMLingua2; indexing and normalization are per system | the runner's `--embedder` defaults to hash; `run_all.sh` and the local entry use the shared MiniLM; with `--embedder native` the gateway still gives hash embeddings to Mem0/Nemori/Hindsight | the same model name does not guarantee the same index, dtype, length or tie order; MemoryBank banks built on different devices cannot be restored on each other |
| LLM configuration | the new entry defaults to Qwen3.8-Flash, the same model for every role, thinking off, MemCut's temperature 0 | the local eight-system entry uses the same Qwen, keeping upstream formation/planning temperatures and caps (A-Mem adds json_object) | this is a comparison under the same answerer configuration, not a reproduction with the papers' original models; internal sampling differences still affect memory |
| Abnormal content | stop and keep the reply when sources, key types or completion status are not satisfied; an unavailable answer is recorded and the run continues; transport failures see §7 | the adapters count refusals and parse/local-search failures and return empty or skip; from v2 the local entry records refusals and skips them the same way, retries 429/5xx and unsent requests with back-off, resends other 4xx on the next run, and unknown outcomes need `resolve --retry` | invalid sources cannot be deleted correctly, and sources must not be invented or scored zero; the failure policies do differ |
| Export | deletions per claim/state, native/residual recovery statistics, available queues and run evidence | LoCoMo per-question answers/context/F1, cost and paired data; the local `COSTS.csv` is the actual HTTP receipts, not a unified token ledger | the new aligned entry does not automatically produce the LoCoMo 1540-question ZIP or the same cost table |

Code: [deletion closure](../../memcut/source_anchored_v2/whole_object_deletion.py), [MC scoring](../../memcut/source_anchored_v2/evaluation.py), [early stop](../../memcut/answer_execution/early_stop.py), [unavailable readouts](../../memcut/aligned_s012/answers.py), [transport policy](../../memcut/aligned_s012/transport.py), [source execution](../../memcut/source_anchored_systems/runner.py), [SimpleMem execution](../../memcut/simplemem_s012/runner.py). ## 3. MemoryBank specifics

Code: [formation/sources](../../memcut/source_anchored_v2/memorybank.py), [retrieval adapter](../../memcut/native_memory/memorybank.py), [new configuration](../../memcut/aligned_s012/runtime.py).

| Item | MemCut ↔ LoCoMo | Reason and effect |
|---|---|---|
| Grouping | MemCut uses the full session timestamp and alternating user/assistant pairs; LoCoMo merges by day YYYY-MM-DD and may leave an empty query/response when speaker alternation is incomplete | EP session/turn is the source address. The 272 sessions of LoCoMo10 fall on 272 distinct dates, so day merging never actually triggers; the real differences are the key format (date or full timestamp, which affects document length, the 200-character expansion and sorting) and empty query/response at session edges |
| Speakers/templates | MemCut keeps the original user/AI roles, the configured user_name and the native summary templates; LoCoMo replaces labels and summary names with speakers A/B and replaces "the AI Companion" in portrait sentences with speaker B's name (LongMemEval and MemCut keep AI Companion) | the EP assistant is not written as a second user; personality/summary texts may differ |
| Objects | both have per-group history/personality and global summaries, but MemCut groups by session and LoCoMo by day; MemCut keeps parent sources for every stored object | deletion must maintain all objects, not only the fields the reader sees |
| Global portrait | the global portrait and global history derive from all turns, so any deletion removes them: the native prompts of S0/S1/S2 have no portrait (one empty personality line), Full has it | a direct consequence of the protocol; must be stated in the paper |
| Formation requests | MemCut temperature 0; LoCoMo native 0.7 with the original sampling parameters. The 400 formation cap is kept; MemCut formation lets length replies enter the summary path, answers must finish normally | continues the formation convention; one can neither claim formation never truncates nor re-judge historical formation by QA rules |
| QA k | MemCut explicitly 10; the baseline default 100; both keep the adjacency expansion and the CHUNK_SIZE=200-character logic; deletion candidates use an independent top-20 | k=10 is the accepted main-experiment setting and is not changed to 100 for alignment; hits and lengths will differ |
| Index/representation | MemCut uses the old LangChain/real FAISS and the loader's summary representation; the baseline uses NumPy and the default non-strict_repr text | snapshots/deletion depend on FAISS; the baseline is portable to avoid the old library; distances, tie order and literal representation are not guaranteed equal |
| Renderer | MemCut uses the original chatglm_belle_eval template, personality and empty recent history, then the MC outer layer; the baseline passes memory/portrait text to the bridge | the outer layer handles the question type and the inner layer keeps native memory; the final prompts are not verbatim identical |
| Read side effects | MemCut reads a docstore copy with forgetting/reinforcement frozen; the baseline also leaves forgetting off by default but has extra optional branches | S0/S1/S2 differences should come from the specified deletion, not from decay while answering; forget/path B is out of scope for this round |
| Retries | MemCut does not copy native multi-generation or shortened-context retries; the baseline port keeps the content-failure paths (refusal→empty, shortened-context retry), and in the local Qwen entry refusals are recorded and then take the same path | one real content/cost identity is kept; success is reused only by exact request |

## 4. Nemori specifics

Code: [this round's merging/prediction-correction/tail batch/rendering](../../memcut/aligned_s012/nemori.py), [storage/retrieval/rendering](../../memcut/source_anchored_systems/nemori.py).

| Item | MemCut ↔ LoCoMo | Reason and effect |
|---|---|---|
| Version | MemCut v0.1.1, LoCoMo v0.2.0 | mechanisms are restored in the snapshot-capable system without migrating database/prompt/model structure; generator and state-machine differences remain |
| Merging/learning | enable_episode_merging and enable_prediction_correction on, direct-per-episode extraction off | aligns the core mechanisms; the old lightweight Full cannot serve as this round's configuration |
| Batching | MemCut: full batches of 20, segmentation within the batch, merge attempted only for the first group (v0.1.1 as is); the tail batch follows the v0.1.1 LoCoMo flush, one episode for the whole tail, no segmentation, no merge. The baseline default flushes 2 messages first and then the rest, segments large batches at the native 80 and runs each episode through the new-version pipeline | each version's executable rules are kept; prior knowledge, merged objects and call counts differ |
| Prediction over old knowledge | MemCut uses real Chroma semantic search; v0.1.1 fetches 20, inspects the first 10 and filters at similarity ≥ 0.85; the baseline's new-version prediction uses semantic search 20 without threshold | numbers are not changed mechanically; the old version's cold start, relevant-knowledge filtering and no-relevant-knowledge branch also affect results |
| Generation parameters | MemCut temperature 0; segment/episode 8192, merge decision 4096, merge content and PC 8192; JSON calls carry `response_format: json_object` (v0.1.1 does not pass it, the 0.2.0 baseline passes it for JSON calls and not for prediction text). The baseline uses segment 0.2 and 0.7 elsewhere, with generator caps such as 4096/2000 | each version's request configuration is kept; formation sampling differs, so score differences cannot be attributed wholly to merging or the reader |
| Roles/time | MemCut user/assistant plus source metadata; episode created_at takes the source time, a merged episode takes the time of the new group; a semantic's time is that of its source episode and from v2 is shown in the native prompt. The baseline uses real speaker names, server-side time-type adaptation and the new-version semantic time policy | fixed source identity makes replay possible; ingestion day is not automatically the EP event day |
| Backend | MemCut local repository + Chroma/HNSW + BM25 (spaCy en_core_web_sm, refuses to start when missing); the baseline PostgreSQL + Qdrant. The 0.2.0 baseline buffer stores message bodies as JSON literals, so bodies in all prompts carry quotes and escapes (upstream behaviour, reproduced faithfully by the baseline) | per-claim branch recovery must not require several database services; not the same index implementation |
| QA | both episode 10, semantic 20, raw messages of the first 2 episodes shown; MemCut old Chroma, the baseline new-version memory.search/vector | similar counts do not mean the same ranking and fields; MemCut deletion candidates go through UnifiedSearch top-20 separately |
| Rendering | MemCut uses the old ANSWER_PROMPT/format_memory_lines, fills times for episode and semantic lines by the LocomoSearcher rule, then the MC layer; the baseline uses the new-version date text, episodes first, then the bridge | keeps the bound native readout; recovery input is not changed for a short-answer budget |
| IDs/order | MemCut content-derived uuid5 (36-character uuid format like upstream uuid4), serial commit of merges and corrections, merge timestamp from the source time, reproducible state identity when rebuilding Full; the baseline defaults to `deterministic_ids=true`, i.e. uuid5(conversation:counter), so reruns hit the cache, serial processing | only replaying uncommitted batches hits the original replies; formation that depends on prior knowledge cannot be parallelized freely |
| Source closure | a merge inherits the old episode plus the current group; a correction inherits the old semantics that actually entered the prediction plus the current episode | deleting old knowledge must delete new knowledge generated from it; forward-QA foreign keys or turn hints cannot replace the closure |
| Deletion | matched objects are deleted whole and the indexes synchronized; no episode/statement is rewritten | no regeneration; LoCoMo has no deletion process (both Nemori versions do have deletion APIs) |
| Silent handling | upstream silently handles unknown IDs returned in merge decisions and missing fields in merge/PC replies; MemCut does the same and counts them in `progress.diagnostics` | behaviour matches upstream, counts visible |

The closure can be large; this is conservative dependency tracking and does not prove that every source is semantically necessary. Prediction attribution links parent objects by the semantic text actually sent to the prediction, without extra LLM attribution calls.

## 7. Execution boundaries and facilities not yet shared

An explicit run executes build → delete → answer → report. There is no pilot, no 30-question gate, no separate audit, no AST observer and no AUDIT.json precondition. Configuration/input binding, source validity and atomic checkpoints are basic correctness checks, not an extra evaluation period.

| Item | Current implementation and reason |
|---|---|
| Caching | MemCut reuses by exact request identity; the local LoCoMo transport additionally distinguishes logical call occurrences and merges identical requests still in flight within the same unit into one dispatch (a client-timeout resend no longer pays twice). The two sides differ on whether an identical prompt is a separate logical call, so costs cannot be added together |
| Transport failures | both entries use one policy: 429/408/409/5xx and unsent requests are retried with back-off within the same dispatch (not billed; MemCut logs them to `requests/TRANSPORT_RETRIES.jsonl`); a content refusal is saved as that request's result and not resent on rerun; other 4xx stop and are archived automatically and resent on the next run; dispatches with an unknown outcome (timeout, disconnect after sending) stop and are resent after `resolve --retry` archives them (may be billed twice; recorded in `ARCHIVED.jsonl`) |
| Checkpoint granularity | MemCut has Full/checkpoint/claim branches, a single unavailable answer no longer interrupts the answer stage, and a Nemori checkpoint with a non-empty buffer can be restored; the eight-system baseline has no unified Full recovery protocol, usually rebuilds the conversation lifecycle and relies on the reply cache, and when one system stops the others keep running, with the failed questions resumed by the same `run` |
| Lock | the aligned entry takes `MEMCUT_PAID_LOCK` (default in this package: `outputs/MEMCUT_PAID.lock`); pointing the local LoCoMo `--paid-lock` to the same file makes the two mutually exclusive; workers wait for the lock instead of failing, and the directory of `--paid-lock` must exist. Other MemCut entries do not take this lock, so it is **not a machine-wide global lock**; tests use a temporary lock |
| Resources/limits | local LoCoMo: a hard cap per system, checked before dispatch, raised with the `ceiling` command; waits before start for disk ≥ 12 GiB and memory pressure (macOS only), which is not a scheduler. The aligned entry has no such waiting or caps; attach them separately when a hard limit is needed |
| Status | status is read-only and shows pending dispatches; running a completed run again returns SUMMARY; individual stages follow the checkpoints. Previously stopped LoCoMo experiments are not resumed by this |
| Release identity | the portable package changes ROOT, upstream paths and code identity, so a new PLAN is required; runs frozen in another workspace cannot be resumed. Upstream checkouts, models, banks, replies, results and keys are not pushed |

## 8. Using the new entry

Run from the toolkit root; prepare a separate Python environment, pinned upstreams and local models as described in `docs/USAGE.md` (the Nemori environment needs `python -m spacy download en_core_web_sm`). The commands below are examples and do not mean an experiment was started:

```bash
python run.py aligned prepare --system lightmem --output outputs/NEW_RUN \
  --source SOURCE.json --contracts CONTRACTS.json --annotations ANNOTATIONS.json
# prepare does not call the API; run builds the bank and executes deletion/answering.
# The key goes in the DASHSCOPE_API_KEY or MEMCUT_MODEL_API_KEY environment variable, never in a parameter file.
python run.py aligned run --run outputs/NEW_RUN
python run.py aligned status --run outputs/NEW_RUN
# When stopped at a "dispatch with unknown outcome": list first, then archive and resend after confirming
python run.py aligned resolve --run outputs/NEW_RUN
python run.py aligned resolve --run outputs/NEW_RUN --retry
```

Available systems are memorybank/nemori/lightmem/simplemem, plus the two RAG controls turnrag/sessionrag (`--native-eval-k`; `--accept-coverage` for Session RAG). `python tools/memcut_s012.py ...` is the equivalent direct entry. MemoryBank uses the separate old-LangChain environment, SimpleMem the LanceDB environment, and Nemori/LightMem the source-systems environment; do not force all dependencies into one environment. The default is Qwen3.8-Flash with thinking off; model/endpoint can be overridden explicitly at prepare, Qwen3.8-Flash accepts only the Beijing Bailian endpoint, and this is validated at prepare. To share the paid lock with a local LoCoMo run: `export MEMCUT_PAID_LOCK=<the same file as --paid-lock>`.

## 9. Scope of changes and verification

v1 added the unified entry and the scoped runtime; restored Nemori merging/prediction-correction, real parent sources and stable replay; changed LightMem's effective compression rate; and accepted SimpleMem's missing-field defaults. The v2 changes are in §0. Historical runners and configurations are unchanged; only the new entry selects the new behaviour.

Tests (zero API): the default `pytest` gives **162 passed / 9 skipped** (after adding the RAG controls; the new `tests/test_aligned_rag.py` has 7 tests: a complete run of each control, unavailable readouts, the coverage gate stopping before a paid request, completing after acceptance, and RAG-only options rejected for other systems. Previously 155 passed; the new `tests/test_aligned_v2.py` covers EP14/15-style trial names, prepare atomicity and endpoint validation, the transport policy, unavailable readouts and available queues, MemoryBank early stop, SimpleMem defaults, LightMem tail recording and formation diagnostics). The native tests run in environments with the upstreams installed, with replies and embeddings still from fixtures: Nemori (chromadb, spaCy en_core_web_sm) tail flush, semantic time, buffer checkpoint restore and the existing merge tests pass; SimpleMem (LanceDB 0.25.3, Tantivy 0.25.1) rejected keywords, single-threaded FTS and the end-to-end run pass; LightMem (real LLMLingua-2 structure, random weights) tail-probe dropped turns match an independent observation, and a complete run with one truncated answer goes through all four stages and a rerun sends nothing. The portable default tests do not require the four upstreams, the native tests are skipped by environment condition, and a skip must not be counted as a pass.

Not claimed: that all four systems have run through real full EPs, that the new Nemori equals v0.2.0, that all upstream tests pass, that no text is truncated by encoding, that source coverage equals semantic sufficiency, or that budgets are equal or only the reader differs. LoCoMo took part in method development and is a development benchmark; scores must be bound to specific versions, prompts, models, inputs and budgets.
